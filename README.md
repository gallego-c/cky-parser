A Python coursework project exploring the **Cocke–Kasami–Younger (CKY / CYK)** algorithm, **Chomsky normal form (CNF)** conversion, and **probabilistic context-free grammar (PCFG)** parsing.

Developed for **Advanced Programming and Algorithms**, the project separates source code, sample data, historical results, and development notebooks while retaining the original function-based implementation.

---

## Features

- **CKY recognition:** check whether a string can be generated by a grammar in CNF.
- **CNF checking:** inspect productions with `es_cnf`.
- **CNF conversion extension:** explore epsilon handling, unit productions, binarization, and terminal replacement.
- **Probabilistic CKY:** compute the maximum probability of a derivation using weighted productions.
- **Batch examples:** load multiple grammar blocks and candidate strings from text files.

This is an educational implementation with known limitations, documented below. The conversion routine is not a complete general-purpose CFG normalizer.

## Theoretical Background

### 1. Chomsky Normal Form

CNF productions have the following forms:

- `A -> B C`, where `B` and `C` are nonterminals.
- `A -> a`, where `a` is a terminal.
- Optionally, `S -> ε` when the language contains the empty string, with the appropriate start-symbol restrictions.

The routine in [src/ext1.py](src/ext1.py) is organized into five stages:

1. Introduce a new start symbol when needed.
2. Process epsilon productions.
3. Expand unit productions.
4. Split long productions into binary productions.
5. Replace terminals in binary productions with auxiliary nonterminals.

These describe the implemented stages; they do not guarantee correct conversion for every grammar.

### 2. Deterministic CKY

The parser builds a triangular table containing the nonterminals that derive each substring:

- **Initialization:** add `A` to `T[i, i]` when `A -> word[i]` exists.
- **Combination:** add `A` to `T[i, j]` when a rule `A -> B C` matches entries in `T[i, k]` and `T[k+1, j]` for a split point `k`.
- **Acceptance:** check whether `S` appears in the cell covering the entire string.

The implementation indexes productions by their right-hand side to look up matching parent nonterminals.

### 3. Probabilistic CKY

For each compatible binary rule, the probabilistic parser evaluates:

```text
P(A -> B C) × best(B, left substring) × best(C, right substring)
```

It keeps the maximum over productions and split points. The result is the **best derivation probability**, not the sum of all derivation probabilities. Parse-tree reconstruction is not implemented.

## How to Run

### Requirements

Python 3. The Python source files use only the standard library; no external packages are required. Opening notebooks requires a compatible notebook environment.

### Execution

From the repository root:

```sh
python src/main.py
```

The script runs the base CKY examples, extension 1, and extension 2 in sequence. Input paths are resolved relative to the repository location, independently of the working directory.

Results are printed to the terminal. To save the console output:

```sh
python src/main.py > output/run_results.txt
```

The existing files in `output/` are historical results and are not updated automatically. Function names, variable names, and console messages retain their original language; comments in the Python source files are in English.

## Input & Output Format

### Standard Grammars

Use `->` for productions and `|` for alternatives. Put candidate strings below the rules and separate grammar blocks with a blank line.

```text
S -> A B
A -> a
B -> b
ab
ba
```

Right-hand sides support spaced symbols (`A B`) and the original compact notation (`AB`). Candidate strings are processed character by character.

For the rules above, the direct `cky` function returns `True` for `ab` and `False` for `ba`. The current file loader also includes rule lines in the candidate list, so the full script prints additional unintended checks.

### Probabilistic Grammars

Place a probability in square brackets after each alternative:

```text
S -> AB [1.0]
A -> a [1.0]
B -> b [1.0]
ab
ba
```

For this grammar, `cky_probabilistico` returns `1.0` for `ab` and `0.0` for `ba`. It expects a grammar suitable for CKY; weighted CNF conversion is not implemented.

## Implementation Notes

The original coursework algorithms are preserved, including these limitations:

- Both loaders add rule lines to the candidate-word list.
- The standard loader drops epsilon alternatives, and deterministic CKY does not handle an empty candidate string.
- CNF conversion has incomplete nullable and unit-rule handling and does not generally guarantee language preservation.
- In the base runner, converting a non-CNF grammar overwrites the grammar identifier before it is used as a dictionary key, which can cause an error.
- Both parsers recognize from `S`, while the converter can introduce `S0`.
- Probabilistic CKY returns zero for an empty string, does not fully validate CNF or probability normalization, and substitutes `1.0` for some malformed probability values.

The notebooks remain unchanged as historical development files, including their original comments and internal paths.
